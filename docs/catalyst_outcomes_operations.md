# 재료 이후 상승 추적 운영

2026-11-11. 기존 AlphaLab 결정·CIO 승인·주문·Telegram과 분리된 연구 원장이다.

## 화면과 API

AI Brain 대시보드와 제갈공명 뉴스·재료 검증 화면의 **재료 이후 상승 추적**.
`GET /api/admin/mirofish/kongming/catalyst-outcomes`는 관리자 또는 활성 제갈공명
이용권만 허용한다. `page`, `page_size`(최대50), `symbol`(숫자6자리),
`filter=all|rising`만 받으며 GET은 공급자 호출·갱신·파일 생성을 하지 않는다.
응답은 private/no-store이고 출처/개인 인증정보가 아닌 화면 필드만 투영한다.

## 입력과 관측

- 보존된 검증 tasks 전체(비활성 포함), 기사 snapshot, Omni news_events,
  급등 역추적 evidence/history를 합친다. 원문 전체 또는 시장 전체가 아니다.
- 현재 종목 사전과 제목·종목 연결이 일치하는 재료를 사용한다. 스포츠,
  비재료, 지원하지 않는 혼합 문자 종목코드, 미래 시각은 제외 사유를 저장한다.
- 별칭을 원장에 보존해 재전송·출처 교체가 새 사례나 최근 수신으로 바뀌지 않는다.
  철회 표식은 원본 사례를 지우지 않고 통계와 후보에서 계속 제외한다.
- 최초 수신일 **다음 거래일 종가**에서 5/10/20거래일 뒤 종가까지 관측한다.
  진입 비용10bp, 청산 비용30bp(수수료5/슬리피지5/매도세20) 가정이다.
  최대 상승·하락도 종가 기준이다. 실체결, 장중 경로, 인과관계의 증명이 아니다.
- 과거 가격은 Naver 수정종가이며 당시 수정주가·기업행사를 독립 검증한 값이
  아니다. 현재 종목 사전의 생존 편향과 기사/수익 구간 중첩도 남는다.
  같은 날짜라도 NAVER 수정종가와 KIS 종가가 다를 수 있으며 두 가격을
  하나의 체결 수익 계산에 혼합하지 않는다.
- 가격과 독립된 KIS 거래일의 open/closed 전 일자를 확인한다. 보존 달력 부족은
  별도 캐시에 실행당 최대3회 보강하고, 누락·충돌은 날짜를 건너뛰지 않는다.
- 최초 완료 가격·수익·출구일은 보존한다. 실제 가격 수정은 영구 통계 제외,
  일시 자료 누락은 blocked로 표시하며 동일 값 복구 시 다시 확인한다.

## 현재 후보 정책 v1

동일 종목의 당시 수신 사례 중 10거래일 비용 반영 상승 관측이 있고 최근30일
독립 수신 재료가 있어야 한다. 같은 종목/수신일은 하나의 통계 코호트다.
수입한 과거 기사(import)는 표시만 하며 후보 통계에서 제외한다.

종가>20일평균>60일평균, 최근5거래일 상승인 예비 종목 최대30개를 KIS
완료 일봉100개로 확인한다. 마지막61일이 공식 거래일과 연속 일치해야 하고,
거래량0·가격 이벤트 경고가 없어야 한다. 20일 평균 거래대금10억원 이상,
시세 취득96시간 이내·기준일7일 이내를 적용한다. 실행당 KIS 최대12종목이며
성공한 입력은 해당 완료 거래일 동안 재사용한다. 오늘 미완료 일봉은 사용하지 않는다.

점수 = 40×clip(20일상승률/20%,0,1) + 30×min(상대거래량/2,1)
       + 20×과거상승코호트/완료코호트 + 10×min(완료코호트/10,1).
최대3종목을 표시하며 점수는 상승 확률이 아니다. 참고 가격은 최근 완료 종가,
손절 폭은 ATR14×2와 기준가8% 중 작은 값, 목표는 그 폭의2배다.
현재 매수가·주문·계좌 비중 또는 기존 CIO 승인을 대체하지 않는다.

이 규칙은 첫 운영 결과 확인 전에 고정했다. 같은 과거 구간을 보고 계수를
반복 최적화하지 않는다. `publications`는 발표 시각/슬롯/후보를 보존하고
향후 별도의 검증 구간으로 평가한다. 슬롯 둘을 독립 거래 표본으로 세지 않는다.

## 예약·복구

Windows MiniPC `C:\bitman_marketfloww` / 작업 `MarketFlow-Catalyst-Outcomes`.
설치: `powershell -File scripts/install_catalyst_outcomes_task.ps1`.
한국 시간 매일10:00/15:00, 기동 시와5분 간격 복구 트리거.
`python -m scripts.run_catalyst_outcomes`는 완료 슬롯에서는 수집 없이 종료한다.
프로세스 중복 금지, 파일 잠금, 실행180초 예산/작업4분 한도를 사용한다.

저장 위치 `data/catalyst_outcomes/`: `outcomes.sqlite3`, `calendar.json`, `prices/`.
SQLite 트랜잭션으로 사례·스냅샷을 함께 게시한다. 공급자 오류는 이전 스냅샷을
보존하고 failed/partial을 표시한다. 원본 급등 추적이 partial이지만 저장 기록을
모두 읽었고 로컬 단계가 끝났으면 `complete_with_gaps`로 슬롯을 끝내며 화면은
계속 partial이다. 이 상태를 정상 완전 수집이라고 표시하지 않는다.
다음10시/15시에 새로운 원본을 읽고, 실패·미완료 입력만5분 복구에서 이어간다.

운영 확인은 작업 최근 결과, 공개 /healthz·/api/health, 인증된 GET의 pagination,
자료 시각·coverage·실제 화면을 함께 확인한다. `.env`나 키·토큰을 출력하지 않는다.
정책 변경은 새 정책 ID/새 원장에서 평가하며 기존 완료 결과를 덮어쓰지 않는다.
