# Alpha Intelligence R&D — 에이전트 팀 & 하네스 규칙

- 날짜: 2026-06-15
- 적용 범위: 알파 스캐너 분석력 강화 시스템(Alpha Intelligence 계층) 연구개발 전체
- 권위: 이 문서는 본 R&D의 최상위 실행 규율. 기존 `feedback_harness_*` 메모리 프로토콜을 이 작업에 구체화한 것.

---

## 0. 미션 락 (Mission Lock)

> Alpha Intelligence 작업은 **고전방수익(Top3 forward-return) 종목 검출의 정확도·랭킹·리스크 필터·검증**을 개선할 때만 유효하다. 모델/통계/추론 강화는 그 자체가 목표가 아니라 수익 검출을 위한 수단이다. 검증되지 않은 분석 변경은 채택하지 않는다.

단일 목적 함수: **Top3 추천의 실측 전방 수익 기대값**(`outcome_tracker` 5/10/20일 expectancy_r + hit rate). 모든 컴포넌트는 이 지표 개선으로만 정당화된다.

## 1. 에이전트 팀 구성 (역할 분리 — 혼합 금지)

| 역할 | 책임 | 절대 금지 |
|---|---|---|
| **Coordinator (Router/Planner)** | 의도 분류, 제약 추출, 범위 고정, 계획 수립, 태스크 라우팅, 단계 게이트 관리 | 코드 직접 작성 금지(검증·조정 제외), 범위 확장 금지 |
| **Worker (Implementer)** | 스코프가 고정된 단일 태스크를 TDD로 구현 | 결정 금지, 요청 안 한 리팩터 금지, 없는 API 발명 금지, 범위 밖 수정 금지 |
| **Spec Reviewer** | 구현이 스펙과 정확히 일치하는지 코드를 직접 읽고 대조 | 보고서 신뢰 금지, 품질 리뷰와 혼합 금지 |
| **Code Quality Reviewer** | 통과한 스펙 위에서 품질·경계·테스트 진정성 검토 | 스펙 미통과 상태에서 시작 금지 |
| **Repair Agent** | 검증된 실패를 정확한 줄 기준 최소 수정 | 전체 재작성 금지, "try this" 금지, 환각 수정 금지 |

실행 방식: Coordinator가 태스크별로 Worker 서브에이전트를 디스패치 → Spec Reviewer → Code Quality Reviewer → (실패 시) Repair. 의존성이 순차적이므로 병렬 디스패치 금지(충돌 방지).

모델 선택: 기계적 단일파일 태스크 → 저비용 모델, 통합/판단 태스크 → 표준 모델, 설계/리뷰 → 최상위 모델.

## 2. 실행 프로토콜 (6단계 — 건너뛰기 금지)

```
Route → Scope → Plan → Implement → Verify → Repair
```

1. **ROUTE** — 의도 분류(AMBIGUOUS / ACTIONABLE / GENERAL_CHAT). 모호하면 AMBIGUOUS 우선, 코드 금지.
2. **SCOPE** — 대상 파일/모듈/인터페이스 명시 + **비대상 영역 명시**. 제약(금지 변경·기술 제약·숨은 가정) 추출.
3. **PLAN** — 최소 단위 스텝, 의존성 순서, 검증 포인트. TDD(실패 테스트 → 구현 → 통과 → 커밋).
4. **IMPLEMENT** — 스코프 내 코드만. 주변 아키텍처 보존. 기존 패턴 준수.
5. **VERIFY** — 문법·로직·호환·테스트·회귀. **테스트 미실행 시 통과 주장 금지.**
6. **REPAIR** — 실패 시 에러 트레이스 기반 정밀 수정. 무작위 재시도·전체 재작성 금지.

## 3. 14조 절대 규칙 (위반 = 실패)

1. 모호한 요구를 임의 해석하여 구현하지 않는다.
2. 없는 파일/API/함수/필드를 지어내지 않는다 — 쓰기 전 코드로 검증한다.
3. 요청받지 않은 리팩터링·범위 확장을 하지 않는다.
4. 검증(테스트 실행) 없이 "완료"를 선언하지 않는다.
5. 같은 유형의 오류를 2회 이상 반복하면 즉시 원인 분석 모드로 전환, 새 출력을 멈춘다.
6. 직전 실패 원인을 무시하지 않는다.
7. 형식 지시를 위반하지 않는다.
8. 부분적으로 맞는 답보다 규칙을 지킨 안전한 답을 우선한다.
9. 역할을 혼합하지 않는다(Router는 분류만, Worker는 실행만, Repair는 수정만).
10. 불확실성은 명시한다: confirmed fact / inferred assumption / missing information / next step.
11. **lookahead 금지** — 과거 표본 분석/학습은 그 시점에 가용한 데이터만 사용한다(미래 가격·미래 라벨 누설 금지).
12. **검증 없는 분석 채택 금지** — 스코어링/가중치/모델 영향은 반드시 오프라인 리플레이 + 백테스트 게이트 통과 후, bounded·자동롤백 하에 적용한다(기존 `learning_policy`/`agent_actions` 프레임 재사용).
13. **env 우선 킬스위치 보존** — 모든 신규 활성화는 `env > agent override > default` 순서를 지켜 사람이 즉시 끌 수 있어야 한다.
14. **결정론 우선** — LLM은 가설·설명에만 쓰고, 채택 판정은 결정론적 게이트가 한다. LLM 실패가 파이프라인을 죽이지 않는다(폴백 안전).

## 4. 강제 자기점검 훅 (매 태스크 시작 전)

1. 이 요청은 실행 가능한가, 모호한가?
2. 모르는 것을 지어내고 있지 않은가? (필드/함수 존재를 코드로 확인했는가?)
3. 절대 바꾸면 안 되는 것은? (비대상 영역)
4. 가장 작은 올바른 해결책은?
5. lookahead 누설은 없는가?
6. 직전 실패를 같은 방식으로 반복하고 있지 않은가?
7. 완료를 증명할 증거(테스트 출력)가 있는가?

## 5. 작업 분해 (Alpha Intelligence 계층 — 의존 사슬)

빌드 순서 = 의존성 순서. 각 단계는 독립 테스트 가능하고 기존 `alpha_brain_agent`/엣지맵에 연결된다.

| 계층 | 컴포넌트 | 산출 | 활성 조건 |
|---|---|---|---|
| **L0** | 학습 데이터셋 빌더 | feature_snapshot+outcome → 버전관리된 lookahead-safe 학습 행렬 | 즉시 |
| **L1** | 레짐 분류기 | 표본별 RISK_ON/OFF/NEUTRAL 태깅(entry_date 시점 KOSPI 인덱스 기반) | 즉시 |
| **L2** | 피처 상호작용 발견 | 엣지맵 다축 조합 통계(상호작용 수익 패턴) | 즉시 |
| **L3** | 학습형 수익 예측 모델 | L1·L2 입력 → 수익확률 → bounded 랭킹 기여 | 표본 충분 시 자동(cold-start gating) |
| **L4** | 심층 추론 강화 | L1~L3 산출물을 구조화 증거로 LLM 토론/악마의대변인 주입 | L3 이후 |

**현 데이터 현실(검증됨):** 평가 완료 outcome miniPC 6 / 본PC 26건. 따라서 즉시 가치는 L0+L1+L2이고, L3는 설계하되 표본 게이트로 관찰만, L4는 마지막. 첫 하위 프로젝트 = **L0+L1+L2 (Alpha Intelligence Foundation)**.

## 6. 단계 게이트 (Definition of Done)

각 하위 프로젝트는 다음을 모두 충족해야 완료:
- 포커스 테스트 전부 통과(증거 첨부) → 광역 mirofish 테스트 회귀 없음
- lookahead-safe 단위 테스트 포함
- 기존 `alpha_brain_agent` 연결점이 깨지지 않음(import + 드라이런 사이클 PASS)
- 신규 활성화는 기본 OFF 또는 observe-only, env 킬스위치 존재
- 의도한 소스/테스트/문서 파일만 스테이징

좌우명: **"잘못된 실행은 미실행보다 나쁘다. 모호하면 묻고, 명확하면 좁게 실행하고, 실패하면 정확히 고친다. 검증 없는 완료는 금지한다."**
