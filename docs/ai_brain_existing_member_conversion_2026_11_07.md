# 기존 AI 브레인 회원 1만 원 추가 전환

기존 AI 브레인 단독 회원이 카카오 문의 없이 앱에서 제갈공명 추가 전환을 신청한다.

## 이용 계약

- 추가 금액은 10,000원이며 서버가 정한다. 클라이언트가 다른 금액을 보내면 접수하지 않는다.
- 승인되면 신청 당시 AI 브레인 만료일까지 제갈공명 권한이 추가된다. 새 30일 이용권이 아니다.
- AI 브레인 만료일, PRO 잔여기간과 일시정지, Ultra PRO 평생 등급을 바꾸지 않는다.
- 활성 AI 브레인 단독 회원만 대상이다. 무기한 수동 권한, 정지 계정, 만료 계정, 기존 묶음/전환 승인 이력은 대상에서 제외한다.
- 이미 신청한 회원은 승인 대기로 안내한다. 거절·철회 후에는 자격이 유효하면 다시 신청할 수 있다.
- 신청 이후 만료·정지·이용권 변경이 생기면 관리자가 승인해도 자동으로 잘못된 권한을 주지 않는다. 입금 사실은 관리자가 확인하고 해당 신청을 처리한다.

## 화면

플랜/등급 관리에서 전환 카드 → 이번 입금 10,000원과 적용 종료일 → 입금자명 입력 → 입금했어요·승인 신청 → 관리자 승인 → 제갈공명 이용.
신청 대기 내역과 관리자 승인 화면은 일반 5만 원 갱신과 1만 원 전환을 구분한다.

## 운영 검증 원칙

전환 API와 접근 제어는 격리 DB의 합성 회원으로 검증한다. 운영 DB는 배포 전 백업하고 회원 이용권·구독 요청 상태/금액 해시를 비교한다. 배포된 코드에서도 같은 격리 테스트를 수행하고 공개 health, 비인증 요청 차단, 배포 번들 일치를 확인한다. 실제 회원의 입금이나 구독 승인을 테스트용으로 생성하지 않는다.

## 배포 전 검증

- 전환 전용 백엔드 테스트 27개: 동시 신청·승인, 한 번의 감사 기록, 승인 대기 중 만료/변경, 실제 제갈공명 API의 403→200 접근 변경, 구 DB 반복 마이그레이션을 검증했다.
- 기존 관리자 수명주기 33개, 관리자 v2 12개, 제갈공명 경로 32개, 판단 접근 제어 7개가 통과했다. Windows 장기 테스트 프로세스의 네이티브 오류는 새 프로세스로 나누어 검증하고 전체 Linux CI에서 다시 검사한다.
- 프런트엔드 전체 1,308개, 린트, 타입 검사와 프로덕션 빌드가 통과했다. 독립 리뷰 후 AuthContext 변환 정보 전달과 대기 중 이용권 변경 시 입금 안내 차단을 보완했다.
- 390px 브라우저에서 전환 카드→10,000원 신청→승인 대기를 실제 격리 API로 확인했다. 관리자 화면의 전환 금액·종료일·승인 확인창을 확인했으며, 승인 요청과 권한 반영은 격리 API로 확인했다. 기존 AI/PRO 기간은 동일했다.
